<KeyTakeaways>
  <p>三人座談錄音與現場照片怎麼不靠人工重聽整理成筆記？用 Codex 串接本機 MLX Whisper 與 SpeechBrain ECAPA 標出講者，再由 Claude Code 對齊題卡照片寫成摘要；聲紋仍需講者名單當錨點，重疊插話與專有名詞還是得人工校對。</p>
</KeyTakeaways>

DevFest 高雄 2026 座談「當設計遇到 AI — 末日崛起」現場開放拍照與錄影。這場九十分鐘的座談我有開手機錄音，最後留下十段錄音檔（Voice Memos `.qta` 檔）與十幾張題卡照片；這批錄音僅留在本機做轉寫與整理摘要，不對外公開原始音檔或完整逐字稿。現場有互動遊戲，非常熱鬧，我沒把握語音辨識能不能認得出來，就算認得出來，還要分出每句話是誰說的，又是一項大工程。一開始我照舊在 Claude Code 裡整理手機語音轉文字的粗稿，講者位置先留空，打算事後憑記憶補上人名；同時抱著試試看的心態，打開另一個視窗問 Codex：「音檔有三個主持人，你能處理成逐字稿嗎？」想先看它能做到什麼程度，再決定下一步。

## 能不能讓 Coding Agent 直接聽錄音？還是得在本機搭管線

我的第一個反應是追問 Codex：「你不是多模態嗎？」它回答，它的多模態不包含把音檔轉成文字，這件事要另外呼叫語音 API；不過它知道我電腦上裝了語音輸入 app Spokenly，提議由它操作 Spokenly 來轉，請我授權，我說 OK。結果操作 Spokenly 那一步被拒絕，於是乾脆完全走本機 CLI，不把私人錄音送到外部轉錄服務。

就算未來 Agent 能直接吃音檔，這場座談的任務還是更適合交給本機專門的語音與聲紋模型：

1. **時間戳穩定度**：後面要拿 `[mm:ss]` 去對現場題卡照片，Whisper 會穩定產出段落時間戳（segment timestamps），一般對話模型聽完不一定對得準。
2. **跨十段錄音的講者一致性**：第 1 段和第 10 段要保證標出來的「主持人 B」是同一個人，靠可儲存的聲紋向量比每次重聽可靠得多。
3. **長度與隱私**：十段加起來超過一小時，本機跑不用付 API 費用，想重跑哪幾段也隨時能重來，音檔更不需要離開電腦。

整體流程最後確定拆成兩段：Codex 負責寫腳本並呼叫本機工具，解決「誰在什麼時候說了什麼」；雲端 LLM 只接觸轉出來的純文字，再由 Claude Code 接手處理照片與整理摘要。這套本機管線用到的核心開源專案如下：

| Repo | 用途 | Stars |
|---|---|---|
| [FFmpeg/FFmpeg](https://github.com/FFmpeg/FFmpeg) | `.qta` 音訊轉檔為 16 kHz WAV | 約 67.5k [2.1.1] |
| [ml-explore/mlx-examples](https://github.com/ml-explore/mlx-examples) | Apple Silicon 本機語音辨識（`mlx-whisper`） | 約 9.1k [1.3.1] |
| [speechbrain/speechbrain](https://github.com/speechbrain/speechbrain) | 講者聲紋特徵擷取（ECAPA-TDNN） | 約 12k [1.1.5] |

## 錄音檔先轉格式，再在速度與錯字之間拉鋸

iPhone 語音備忘錄存下來的是 `.qta` 檔，語音辨識模型沒辦法直接讀，要先用 `ffmpeg` 轉成一般的 WAV。這個檔案裡其實藏了兩條音軌：一條是一般的雙聲道，另一條是 Apple 自家格式的四聲道空間音訊。四聲道那條 `ffmpeg` 解不開（`no decoder found for apple_apac`），反正辨識也用不到，就直接拿一般音軌，轉成 16 kHz 單聲道 WAV：

```bash
ffmpeg -i '新錄音 N.qta' -ar 16000 -ac 1 -c:a pcm_s16le /tmp/festdev_new_recordingN_16k.wav
```

資料夾 `~/Downloads/FestDev` 裡還混著一批 `新錄音 N 2.qta` 的副本，當時先用 SHA-256 確認過第一段的副本內容完全一致，其餘比對檔案大小後，全數只拿不帶 `2` 的主檔處理。

音訊就位後，透過 `uv run --python 3.12 --with mlx-whisper` 在 Apple Silicon GPU 上跑本機推論。第一次啟動花比較久是因為要抓套件與快取模型，在現場處理第一個音檔時就等了不少時間。快取完之後，主力先用 `mlx-community/whisper-large-v3-turbo` 批次產出初稿，5 到 13 分鐘的音檔多半一兩分鐘就跑完；回家後我把全部音檔丟下去跑，一小時後回來就都處理完了。

不過快速模型對台灣口語、英文產品名和技術名詞的錯字率偏高，尤其第 7 段和第 10 段的句子常要靠上下文才猜得出來。為了救辨識品質，我拿第 6 段改測完整版 `mlx-community/whisper-large-v3-mlx`，還順手開了逐字級的 word-level timestamps 對齊——代價是一段五分半的音檔整整跑了約 10 分鐘。

> [!TIP]
> 在本機跑 `whisper-large-v3-mlx` 批次處理長錄音時，若只需要 `[mm:ss]` 分段對齊照片，建議關閉 word-level timestamps。只保留段落時間戳（segment timestamps）能省下 word-level 對齊的額外時間，否則整批十段跑完會非常耗時。

後來重跑第 7 段時關掉了 word-level timestamps，精修版結果也已經輸出成 JSON。只是眼看十份 `.md` 逐字稿都已經產出、足以推進下一步寫作，當下就決定先停在這裡，沒有繼續重跑第 8 到 10 段，也沒有拿這份精修 JSON 去覆蓋原有的 Markdown。

## 十段錄音怎麼讓「三位設計師」一路對回同一個人？

Codex 先讓 Whisper 轉出帶時間戳的文字，再用 SpeechBrain 的 `speechbrain/spkrec-ecapa-voxceleb` 比對每一句的聲音特徵，把聲音相近的歸成同一個人，標成 A、B、C。這時它只知道「這幾句是同一個人說的」，不知道那個人是誰。

接著換我：把三位講者名單和活動背景給它，再指出第一段勞哥的自我介紹（辨識稿寫成「我是老哥，我是設計師」）和「末日博士」這個稱呼，A、B、C 就對上了饅頭、勞哥、史蒂夫•葉。之後的錄音沿用同一組聲紋，跑出來就直接是人名。

剩下的辨識錯字，交給 Claude Code 寫摘要時依前後文一起修，逐字稿就變得很好用。短促插話或多人搶話還是可能標錯，最後仍要自己看過一遍。

## 兩邊匯合：用倒數題卡與時間序把錄音煉成場記

Codex 把錄音十份逐字稿全部標好人名之後，Claude Code 這邊就能直接針對每一份逐字稿產出每段問題的摘要。

座談現場是一題錄一段，雖然偶爾有幾段錄音開頭被截斷、結尾跨到下一題的開頭，甚至有一段把兩題錄在一起，但手邊的照片剛好提供了極佳的對齊線索：

* **題卡倒數計數**：現場題卡照片左上角印了從 `10/10` 倒數到 `1/10` 的題號，先靠這個排出絕對順序。
* **照片拍攝順序**：手機拍照的時間序直接對應錄音的先後。
* **念題內容比對**：沒有題卡照片的第 5 題，或開頭被截斷的段落，就看逐字稿裡饅頭念題的內容來定錨。

對齊完畢後，Claude Code 照著固定結構把每一題收斂成段落：先放用 `sips` 壓縮（JPEG 品質 75、長邊 1600，壓在 200KB 以下）並加上浮水印的題卡照片，圖說填入從照片讀出的現場投票數（`🟢 贊成／未表態／❌ 反對`）與觀眾彈幕；接著寫題目的正反方立場、三位講者各一段摘要，好笑的插曲則獨立拉進 `> [!NOTE]` 區塊。

在整理與對外發布前，也做了兩層機敏資訊與事實把關：

> [!CAUTION]
> Turbo 模型產出的技術名詞與講者口述數字非常容易出錯，務必人工覆核。直接照單全收會把錯字與未經查證的統計數字一起發布出去。

一方面是明確要求 Claude Code 去掉現場機敏資料，講者任職單位與現場提及的企業名稱都做了去識別化。另一方面是處理語音辨識聽錯的地方：Claude Code 先靠背景知識與前後文推回原詞，這正是 LLM 的強項，像是把 UCP 聽成的「Universal comverse Potocl」、把《身心障礙者權益保障法》聽成「生臟權益保護法」、把「末日博士」聽成「奧運博士」或「末日股市」。推不回來的就列出來給我看，由我寫下當時在說什麼；有些是現場的梗，前後文再多也絕對猜不出來，例如養樂多那段講的金額是「六萬零十塊」，以及史蒂夫•葉提到團隊要換成 Claude Design。至於講者口述的法規適用範圍與「美國大學生六成沒從事本科系工作」這類說法，查不到明確來源，就先用 MDX 註解標上「待查證」。

## 心得

回頭看整趟紀錄流程，我只能說，沒想過這件事可以做到這麼好。現場環境、手上的 iPhone 18 Pro，加上我都坐第一排，可能也有差。重點是透過 agent 分工，我在當天會議結束前就 push 了前八篇紀錄與心得，最後這篇比較複雜的座談回家再處理，也是當天就弄完，心智負擔降低非常多。這些工具我平常就知道、也在用，包含聲紋辨識；但如果沒有試試看這樣做，放著一天之後就會開始發懶，想到十個音檔、三個人就覺得很困難。但是現在透過 agent 馬上就能調用這些工具，馬上做出我想要的東西，這種感覺真的很讚，所以記錄一下這個過程。
