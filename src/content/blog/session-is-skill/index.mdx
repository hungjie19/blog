最可惜的 AI session，不是沒有得到答案，而是你明明跟 AI 一起把一件事調到能用了，任務完成後卻直接把對話關掉。

下次再做同一件事，又得重新解釋一次：檔案要放哪裡、格式要怎麼輸出、哪些步驟不能省、哪些地方上次踩過坑。

這篇接在 [Session is Knowledge：把 AI 對話保存成自己的知識庫](/posts/session-is-knowledge/) 後面。前一篇講的是「一次對話，變一份知識」；這篇想講另一半：一次任務，也可以變成一個下次直接呼叫的 Skill / SOP。

## 完成任務不是結束，是 SOP 出現的時候

很多 AI 任務第一次做的時候，不會一次到位。

例如請 AI 幫我總結 session，一開始可能只是請它整理重點。用幾次之後，我會開始補需求：要保留試錯過程、要列未完成事項、要整理相關議題、要存成 Markdown，最後還要放到固定資料夾。

又例如切圖。表面上只是「把這張拼在一起的圖切開」，實際做起來卻有很多細節：怎麼判斷分隔線、輸出檔名怎麼命名、要不要移除角落浮水印、切完要存在哪裡。

這些細節如果每次都重新講一次，很浪費。更麻煩的是，你下次不一定記得自己上次怎麼修正它。

所以我現在會把「任務完成」看成另一個訊號：如果這件事未來還會再做，就應該趁這個 session 還在，把它整理成一個 Skill。

## 最有價值的是那個對話視窗

你跟 AI 一起完成任務的那個對話視窗，是最有價值的流程設計現場。

因為所有困難都在裡面發生過。哪一步 AI 做錯、你怎麼修正、最後接受哪個輸出格式、哪些指令下次可以省略，這些都不是憑空想出來的規格，而是實際跑過一輪後留下來的脈絡。

如果這時候直接關掉，下次只會剩下一個模糊印象：「我之前好像做過一個可以用的流程。」真正有價值的，是那段把流程調到能用的過程。

這也是為什麼我覺得完成任務後，不應該急著離開 session。那個視窗裡有一份活的需求文件，只是還沒有被整理成固定格式。

## 趁脈絡還熱，請 AI 反推出 SOP

我常用的做法是，在任務完成後直接問 AI：

```md
請根據這次對話，幫我整理成一個可重複使用的 Skill / SOP。

請包含：
1. 這個 Skill 的用途
2. 什麼情況應該觸發
3. 使用者可能會怎麼說
4. 執行步驟
5. 輸出格式
6. 這次對話中踩過的坑與注意事項
7. 下次執行時可以直接沿用的規則
```

這段 prompt 的重點，不是叫 AI 寫一篇漂亮文件，而是請它從剛剛的對話裡反推出「下次要怎麼穩定重做」。

如果是 Claude Code 這類可以讀寫本機檔案的工具，下一步甚至可以直接請它建立 `SKILL.md`。如果不是，也可以先整理成 SOP 文件，之後再放進自己使用的 AI 工具。

重點是不要等到下次才回想。到那時你已經忘了很多細節，AI 也看不到這次對話。最好的整理時間，就是任務剛完成、上下文還在的時候。

## Skill 不是寫程式，是寫流程

我以前會直覺把 Skill 想成比較工程師的東西，好像要寫很多程式，或做出一個很完整的工具。

後來用久了才發現，很多好用的 Skill 其實不是程式，而是流程。

它描述的是：遇到什麼情境要啟動、先讀哪些資料、怎麼判斷、輸出要長什麼樣子、遇到模糊情況時要不要問使用者。

用一句話說就是：

```text
SOP = Skill
```

如果一件事有固定步驟、固定輸出，或是你已經修正 AI 很多次才把它做對，它就很適合變成 Skill。

像 session summary、blog 草稿整理、切圖、抓背景圖，這些都不是一次性的靈感任務。它們都有一套你希望 AI 下次照著走的規則。

## Description 要寫使用者真的會說的話

如果真的要把 SOP 做成 Skill，我現在會特別注意 description。

description 不只是功能介紹，它也是 AI 判斷什麼時候要啟動這個 Skill 的入口。所以除了寫「這個 Skill 做什麼」，也要寫使用者實際上可能會怎麼說，把這些句子當成 Skill 的「召喚詞」。

例如切圖 Skill，如果只寫：

```yaml
description: |
  把拼在一起的圖切成單張。
```

這樣的描述，是讓 AI 判斷這個 Skill 的使用意圖。

如果再加上使用者可能會說的「召喚詞」，通常能提高觸發機率：

```yaml
description: |
  把拼在一起的圖切成單張。
  當使用者說「幫我把這張圖切開」、「切圖」時執行。
```

這不是多寫幾個字而已，而是把真實使用語氣也保存下來。因為下次你不會用很正式的規格語言呼叫它，你只會用平常說話的方式說：「幫我切圖。」

## 下次不用重新教

Skill 最有感的地方，是第二次使用。

第一次做 session summary，你可能要講很多：要 Markdown、要存檔、要列出未完成事項、要整理 OpenMemory 候選記憶。

但做成 Skill 之後，下次只要說「幫我總結這個 session」，AI 就知道該走哪套流程。

第一次抓背景圖，你可能要解釋圖片來源、下載位置、metadata、怎麼更新 index。做成 Skill 之後，下次只要說「幫我抓一些極光背景圖」，它就能直接進入那套流程。

這裡省下來的不只是時間，而是心智負擔。你不用每次重新教 AI 怎麼跟你合作。

## 一次任務，變一個技能

AI 對話用久之後，我越來越覺得 session 不只是完成工作的地方，也是流程被萃取出來的地方。

如果一段對話產生了觀念，就把它保存成知識。  
如果一段對話完成了任務，就把它整理成 Skill。

真正保值的不是最後那個檔案，而是你和 AI 一起把流程調到能用的那段脈絡。趁它還在對話框裡，把它變成下次可以直接呼叫的 SOP，下一次你就不用從零開始。
