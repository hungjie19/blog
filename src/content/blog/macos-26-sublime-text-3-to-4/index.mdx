## 警告終於追到我面前

我第一次看到 macOS 26 跳出「Sublime Text 是 Intel app，支援即將結束」的提醒時，第一個反應不是換編輯器，而是：我那些開著、卻沒有存檔的文字會不會不見？

我知道 Apple 從 Intel 轉向 Apple silicon 之後，Intel app 的支援遲早會走到終點。過去 Rosetta 讓這件事可以先放著，直到現在，macOS 26 的提醒才讓它從背景規劃變成眼前要處理的事情。Apple 目前的說明也把這個通知放在 Apple silicon transition 的脈絡裡：Intel app 還能暫時執行，但未來 macOS 版本可能不再支援它。[Apple 的說明](https://support.apple.com/en-ca/102527)

所以我是在現在才決定處理，不是因為我突然想換一個更潮的編輯器，而是因為這個警告已經追到我面前。我真正想保住的，是原本那套隨手記錄、暫時不存檔、需要時再回頭整理的工作方式。

我常常只是突然想到一個 command、一個關鍵字，或看到一句值得記下來的話。這種時候，我不想先建立一個專案，也不想先決定這段文字應該放在哪個分類裡。我只想立刻開一頁，把它寫下來。

這就是我到現在還離不開 Sublime Text 的原因。

## 我把 Sublime Text 當成一本純文字筆記本

按下 `⌘T`，開一個新的檔案，想到什麼就記什麼。可能是一行命令、一個還沒想清楚的概念，也可能只是某個之後想回頭研究的關鍵字。

Sublime Text 對我來說最重要的功能，反而是它不會急著替我安排下一步。它很快，介面也乾淨，開啟之後就能直接輸入。這讓它比較像一本放在桌上的筆記本，而不是一個需要先進入工作狀態的完整工作環境。

過一段時間，我會回頭看這些隨手留下的內容。哪些東西一直重複出現，通常就是我真的想弄懂的主題。接著我才會把它整理、補足概念，慢慢變成正式筆記或文章。

## 乾淨到不會替我做決定

有些編輯器會把 Markdown 裡的連結直接變成超連結。游標一不小心點到，瀏覽器就跳出來；我原本可能只是想改一個字，或複製其中一段文字，整個動作卻被打斷。

有些編輯器則會直接把 Markdown 解析成 preview。這對閱讀完成的文件很方便，對正在隨手記錄的人卻有點礙事。我現在只是想看原始文字、改一個字、複製一行 command，Sublime Text 就讓畫面保持原樣。

它仍然提供我需要的 syntax highlighting、code 檢查與格式整理功能，只是這些能力不會一直搶著站到前面。需要的時候再叫它出來就好。

## 命令列裡太長的文字，也交給 Sublime

這個習慣甚至延伸到命令列。

當 Terminal 裡的文字太長，不適合直接在那裡修改時，我會按下 `⌘G`，交給 Sublime 編輯。連命令列預設啟動的 editor，我也設定成 Sublime。對我來說，這代表不管文字從哪裡出現，最後都能回到同一個熟悉的地方處理。

## 未存檔分頁是方便，也是風險

我很喜歡 Sublime Text 的另一個特性：那些我隨手打開、卻沒有特別存檔的筆記，重開機之後通常還會留著。隔天打開電腦，前一天想到一半的文字還在原來的位置，這種感覺很像把桌上的便條紙原封不動留到隔天。

當然，這種方便也有風險。未存檔分頁可以保留工作狀態，卻不能取代真正的存檔和備份。我把它當成暫存區，等內容開始變得重要，再把它整理到該去的地方。

:::caution
Sublime Text 幫你保留未存檔分頁，不代表資料已經完成保存。重要內容還是要另存檔案，或放進正式的筆記系統。
:::

## 從 ST3 升級到 ST4，幾乎沒有改變工作方式

這次升級是因為 macOS 跳出了 Sublime Text 的 Intel app 警告。我透過 Gemini 確認操作步驟，直接到 [Sublime Text 官方下載頁](https://www.sublimetext.com/download) 下載 Sublime Text 4，解壓縮後用新版覆蓋原本的 Sublime Text 3。

最讓我安心的是，升級之後原本開著的 project、沒有另存的文件，以及那些一直留在 Sublime 裡的暫存內容，都接著在 ST4 裡出現。新版甚至還沒放進 Applications，我從解壓縮的位置直接開啟，它就已經接管原本的工作狀態。

後來再把新版拖進 Applications 取代舊版、更新 Dock，就完成了這次升級。沒有重新建立筆記，也沒有重新整理一堆設定；原本的使用方式幾乎完整接續下來。

## 把 ST4 調回我熟悉的外觀

ST4 的預設分頁和外觀跟 ST3 有些不同，我用了一段設定把它調回比較熟悉的樣子：分頁恢復 ST3 的梯形斜角，程式碼繼續使用 Monokai，整個介面則用深色主題。

```json
{
    // 找回 ST3 的經典梯形斜角分頁
    "file_tab_style": "angled",

    // 程式碼配色維持經典 Monokai
    "color_scheme": "Monokai.sublime-color-scheme",

    // 讓側邊欄和外框維持深色
    "theme": "Default Dark.sublime-theme"
}
```

這裡有一個小細節：`theme` 控制的是側邊欄、分頁和整個 UI 外框，`color_scheme` 控制的是程式碼配色。兩個設定分開處理，才不會以為換了 Monokai，整個編輯器介面也會一起變黑。[Sublime Text 的 Themes 文件](https://www.sublimetext.com/docs/themes.html)也把這兩個概念分開說明。

## 結論：我還離不開 Sublime Text

我留下 Sublime Text，關鍵也不在功能數量。對我來說，它剛好把速度、乾淨和可暫存這幾件事放在一起，讓我想到什麼時可以立刻記下來，想認真處理時又能慢慢把內容接回正式的工作流程。

這次 ST4 的無痛升級，也讓我覺得 Sublime Text 官方真的做得很好：下載、安裝、覆蓋，原本開著的文件和 project 全部都還在，連那些沒有存檔的內容也順利接回來。

很多時候，我們只是害怕面對升級，先把「設定會不會全丟、文件會不會不見、是不是要重新安裝一堆東西」想得很複雜。真的動手之後才發現，這次其實沒有那麼困難 XDD
